AtlasOps

2026 · Research continuation

An agent proposing an action and a person approving that action are two different responsibilities. My work focused on the API boundary between them.

The question

An incident workflow needs to record what was proposed, what was approved, and which evidence supports the decision. A general approval flag is not enough to describe a particular action.

The approach

I extended an inherited platform with authenticated endpoints for exact-action approvals and incident evidence. Rejection paths and integrity checks are part of that contribution, not only successful requests.

Implementation

  1. Incident workflow

    The inherited multi-agent platform proposes actions and collects incident context.

  2. Authenticated API

    Approval and evidence endpoints enforce the documented API contract.

  3. Exact-action approval

    Approval is associated with the proposed action rather than a broad permission to remediate.

  4. Evidence and tests

    Incident records and rejection/integrity tests make the contribution reviewable.

My part in the work

The platform originated upstream and continued as university-team research. My verified contribution is the authenticated API and related test work linked below, not the whole platform or its agents.

Python, FastAPI, authentication, API tests
